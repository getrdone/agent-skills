3B — Where agents over-load or under-load CDSJ. Missing docs, or non-obedience?

Neither, mostly. The honest answer is that nobody can currently tell, because nothing emits what it loaded and nothing logs it. Any claim in either prior plan that agents "are not obeying load lists" is unevidenced. What I can evidence is that the route table itself prescribes both failure modes.

Structural over-load

Route-table row "Build or review HTML/CSS/JS, landing pages, interactions, SEO/AEO/GEO, performance, or accessibility" names six references: web-experience + visual-system + motion-and-premium-ui + design-critique-and-anti-slop + branching-journey + learning-and-writing ≈ 61 KB. visual-system.md then requires repo-root COLOR-PSYCHOLOGY.md (23 KB) whenever a colour decision exists, and CATALOG.md adds DESIGN-DIRECTIVES.md (16 KB) for "any design-bearing task." That is ~100 KB ≈ 25–30 K tokens — for a request that may be "fix the footer contrast." The table has one row for "touch any HTML" and no smaller door. That is over-load by design, and no amount of agent discipline fixes it.

Structural under-load

v3-workflow.md and v3-quality.md are the two most consequential files in 3.2.0 — Journey Concept gate, ideation modes, learner jobs, the review loop, the deterministic audit, the public-write abuse standard. They appear only in the prose override at the top of the SKILL, never in the route table, and they do not exist at the root references/ path. Three independent reasons an agent misses them. Under-load is the default.

The obedience residue

There is a real residue — agents do reach for adjacent files — but it is small compared to the above and it is unmeasurable until (a) paths are unambiguous and (b) runs emit a LOAD list. Sequencing conclusion: fix docs and structure first, then measure obedience, then police it. Building the eval harness first measures a moving target against a contradictory spec.

5D — Progressive stem + append model: race conditions, growth, parsing

The convention is right — one file per stage beats per-agent sprawl, and it matches how Steve actually reviews. But as written on the idea board it will turn into a mush file within a week. Six hard edges, all cheap:

1 · Concurrency

Windows gives no advisory locking here and every agent writes whole files. Two appends inside the same minute = last-writer-wins truncation, silently.

Edge: append is read → verify → write. Before writing, re-read the file and compare its byte length to the length observed at read time. If it changed, re-read and re-append after the newest section. Never rewrite regions you did not author. One writer per stem per session; a second agent that finds a newer trailing timestamp waits or appends after it.

2 · The SELECTED block must be tamper-evident, not just "user-owned"

"Agents must not clobber it" is a wish unless a checker can see a violation.

Edge: fence it — <!-- SELECTED:BEGIN --> … <!-- SELECTED:END -->. Agents hash that region before and after their run and refuse to save on mismatch. A fence also lets the next stage quote it mechanically.

3 · Two selection mechanisms will fight

This is the one nobody flagged. The existing gesture is a trailing ~ on title lines (SKILL.md §Title selection; project-system.md §Piecemeal). SELECTED is a second selection truth. When they disagree — and they will — which wins?

Edge: ~ stays the human's marking gesture, inside a Run's candidate list. SELECTED is generated from ~ marks on request and is the only thing downstream stages read. Marks are preserved, never authoritative twice.

4 · Growth

stem.titles+descriptions+visuals.md accumulates every run of three stages forever. At ~40 candidates per run it is unreadable by run six and expensive to load.

Edge: RUN LOG keeps the newest 5 runs. Older runs move, in one move, to stem.archive.md — one archive per stem, never one file per run. Soft cap 120 KB per stem file; over it, archive before appending.

5 · Parsing

Free-form run headers are unscannable, which defeats the point of one file.

Edge: fixed grammar, regex-checkable:
## Run — YYYY-MM-DD HH:MM PT — agent/model
then exactly ### Reasoning and ### Candidates. Anything else is a lint failure. + in filenames is safe on NTFS and in PowerShell globs; the only real hazard is URL contexts, so never link these files by raw URL.

6 · Which stem is authoritative?

stem.titles.md and stem.titles+descriptions.md can both exist, both with a SELECTED block. Two live sources of truth again.

Edge: the longest compound stem present wins; earlier stems become read-only the moment the next compound is created, and get a one-line SUPERSEDED BY pointer at the top. The compound file's SELECTED opens by quoting the upstream SELECTED verbatim under a INHERITED FROM heading, so drift is visible at a glance.

Canonical shape

# <stem> — titles

<!-- SELECTED:BEGIN -->
## SELECTED (user-owned — agents never edit inside this fence)
1. ...
<!-- SELECTED:END -->

## RUN LOG  (append below; newest at bottom; keep 5, archive the rest)

## Run — 2026-09-10 09:15 PT — claude/claude-opus-5
### Reasoning
### Candidates

Verdict on D: implement, with edges 1–3 mandatory and 4–6 as lint rules. Without edge 3 the convention actively regresses an existing working workflow.

6E — Real stakes vs fear-for-click: a crisp accept/reject test

First, a contradiction that has to be fixed before any test is written

youtube-planning.md §Honest curiosity vs manufactured suspense, rule 8, currently reads: "Do not use fear, guilt, shame, FOMO, scarcity, false urgency, coercion, or deceptive certainty as attention tools." Read literally, that rejects exactly what Steve's brief permits — real fear that is genuinely in the subject matter. Judgment, death, deception and persecution are load-bearing in this material; a rule that bans the emotion rather than the manufacture will either be obeyed (and neuter the work) or quietly ignored (and erode the whole standard). Amend rule 8 to "manufactured fear" and let the test below carry the distinction. One-line edit, high value.

The existing standard is 14 prohibitions. Prohibitions do not decide edge cases; a procedure does. Four questions, all four must pass:

#TestQuestionFails when
1SourceIs the fear in the subject — the passage, the documented event, the real consequence — or introduced by the packaging?Remove the packaging and the fear disappears. Then it was manufactured.
2ProportionWould someone who already knows the full content call this language proportionate?The line implies more danger, more concealment, or more certainty than the content supports.
3ResolutionDoes the content answer the fear it raises — early, plainly, without stretching it out?The stake is raised and never resolved, or the answer is withheld past the point of teaching.
4TransferCould this line be pasted, unchanged, onto an unrelated topic?Yes ⇒ generic bait. (Already rule 12; reuse it, don't restate it.)

Plus one standing constraint: fear may never be the only reason to click. Every line must name a real subject — a passage, a person, an event, a claim. "What's coming will terrify you" fails test 1 and the constraint. "The one verse Adventists and Catholics read the same way" carries real stakes and names its subject.

Where it lands: appended to the existing canonical section in versions/3.2.0/references/youtube-planning.md as "Real stakes vs fear-for-click (accept/reject)", with ~12 labelled examples (6 pass, 6 fail) drawn from actual Final Days topics. No new file — that section already declares itself canonical and other files already point at it. Gate wording in quality-gates.md §1 and §6 gets a pointer, not a copy.
