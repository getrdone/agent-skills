# Palette Integration

<!-- Agent: Codex | Model: GPT-5 | Thinking: not exposed | Date: 2026-09-13 | Added a lean Scripture Journey bridge to the canonical palette-composition skill. -->

Use this bridge only for a new or materially revised color theme. The canonical generator is repository-root `skills/color-palette-composition/SKILL.md`; read its required core-composition reference before producing a theme.

## Journey-specific inputs

Bring these decisions to the palette brief when available:

- the governing promise, audience, subject, and desired learning/emotional posture;
- tone keywords and visual DNA (typography, imagery, composition, material metaphor);
- Scripture/source details, official brand values, and existing theme artifacts that are actually locked;
- final medium: thumbnail, graphic, presentation, landing page, study interface, print, or a mixed system;
- one attention target that should win in two seconds.

Do not invent Scripture symbolism from a color. If symbolism, culture, intended/alternate reading, or a psychology claim materially changes the choice, add `repo:COLOR-PSYCHOLOGY.md`. If a source-specific story name must become CSS tokens, signature gradients, or a developer handoff, add `repo:DESIGN-DIRECTIVES.md` after composition.

## Required result

Use the master skill's field/partner/spark, allocation, provenance, Itten/Munsell, theory-summary, naming, and verification handoff. Preserve source and official names. For a full Journey visual system, then continue into `references/visual-system.md`; do not make the palette bridge recreate its typography, imagery, or motion guidance.

## Lean revision rule

For a simple token correction, one contrast repair, or one fixed swatch replacement that does not change the theme's hierarchy, use `web.repair` or the existing visual-system record rather than reopening palette composition. A request to shift emphasis, rebalance proportions, add/remove a color family, alter a theme's mood, or redesign a page theme is material and belongs here.
