# Content page masthead & surfaces — apply by default

Read this before building or restyling **any content page**: a transcript, article, study
edition, policy page, or any page whose job is reading rather than converting. It is the
distilled result of the 2026-09-18 Final Days transcript session, where the same masthead was
rebuilt four times because each pass fixed only the symptom. Apply it up front and none of it
needs to happen again.

Origin case: `__Final.Days.International/final-days-video-landing-page/versions/10.11.5/`
(`public/transcript/index.html`, generated by `build-transcript.js`).

---

## 0. The one-sentence rule

**Inherit the landing page's identity; never inherit its geometry.** A content page should
carry the same wordmark, brand rule, tagline, palette, type and backdrop image as the page it
sits beside — and its own, much tighter, vertical structure. Copying a landing hero's *height*
onto a page that lacks the hero's *contents* always produces a void.

---

## 1. Masthead height is derived from the page's own negative space

Do not hard-code a height, and do not import the landing hero's. Pick one unit — **the air
above the wordmark** (`--*hero-pad-top`) — and repeat it below the brand block:

```css
.hero   { --t-hero-pad-top: clamp(1.4rem, 4cqi, 2.6rem);
          padding-block: var(--t-hero-pad-top) 0; }   /* bottom 0 — see below */
.hero .wrap { min-height: calc(<brand block> + var(--t-hero-below-wordmark, 2) * var(--t-hero-pad-top)); }
```

Why the bottom padding is 0: the repeated space must live *inside* `.wrap` so that a rule or
headline placed flush at the hero's bottom edge lands exactly `n ×` the top space below the
block. If the space is hero padding *and* element margin, you get double spacing (this cost a
round trip — ~96px of stacked gap).

- `n = 2` is the approved default ("take the space above the wordmark and double it below").
- **"Brand block" means the whole lockup** — wordmark + rule + tagline — not the `<h1>`. From
  the `<h1>`'s baseline the tagline ends up only ~39px above the content, which reads as a bug.
- Ship the multiplier as a token and, if a human is choosy, expose a temporary
  `?below=<n>` query override so they pick a value by eye instead of another round trip.
  Mark such a param for removal before promotion.

## 2. Show a designed image complete — never `cover` it into a short band

`background-size: cover` on a backdrop crops. In a short band a 16:9 designed image gets
sliced to a strip: the flag blew up, the dome left frame, and the composition read as a
"photo bug". If the image is designed (hero artwork, brand backdrop), it is not texture:

```css
.hero::before {
  position: absolute; inset-block-start: 0; inset-inline: 0;
  aspect-ratio: 1672 / 941;                  /* the asset's OWN ratio */
  background: linear-gradient(180deg, transparent 60%, var(--paper) 100%),
              var(--img-hero) center / 100% 100% no-repeat;
  -webkit-mask-image: linear-gradient(to bottom, #000 0%, #000 55%, transparent 100%);
          mask-image: linear-gradient(to bottom, #000 0%, #000 55%, transparent 100%);
  pointer-events: none;
}
```

- Keep `aspect-ratio` in sync with the asset whenever the token is replaced.
- **Decouple backdrop from band.** The band decides where text sits; the backdrop decides what
  the page looks like. The backdrop is allowed to be *taller* than the band and run down
  behind the first content blocks.
- Percentages in the mask are relative to the image layer, so the fade tracks the image, not
  the band. Never crop to "make the image fit" — that is what produced the complaint.
- `cover` remains correct for genuine texture (repeating paper, a veil), where cropping is
  invisible.

## 3. If the backdrop outgrows its band, position the content column

- The band needs `overflow: visible` (drop `overflow: clip`) so the layer can extend.
- The band must own a stacking context (`isolation: isolate`) so its layer paints above the
  page background and below later content.

### 3a. A positioned backdrop paints above *static* content — DOM order does not save you

`position: absolute` puts the backdrop in the **positioned** layer. A plain (static) block and
its inline text live in the block/inline layers *below* it. So any non-positioned child of the
content column is painted over by the backdrop wherever the backdrop still has strength — even
though the column comes later in the DOM. Fix it at both levels:

```css
main.t-wrap { position: relative; }          /* structural: protects unwritten children too */
.t-prologue, .t-section { position: relative; }  /* each surface mirrors the block that works */
```

- The column-level rule is **load-bearing insurance**, not decoration: without it, every future
  static element in the column is silently at risk. Comment it in the source so nobody "tidies"
  it away.
- Symptoms a human reports: "it's barely visible", "the image is almost 100% opaque", "the lead
  has no background", "the text looks washed out". **A surface that exists in the DOM but is
  invisible on screen is a paint-order signature, not a colour or contrast problem.**
- The trap is easy to miss because the sections that *do* carry `position: relative` (usually
  because they paint their own `::before`) look perfect, so only the odd one out is broken.

### 3b. Verifying paint order

- **Verify; do not assume.** With CDP, temporarily add
  `header.hero::before { pointer-events: auto }`, then
  `document.elementFromPoint(x, y)` at the *centre* of the element you expect to be on top: it
  must return that element, not `HEADER.hero`. Leave `pointer-events: none` in the source.
- **The `pointer-events` override is not optional.** The shipped layer is `pointer-events: none`,
  so an unmodified hit test skips the image entirely and returns your content **even when the
  image paints on top**. Running the test without it produced a confidently reported "verified"
  fix that had verified nothing. This is the single most expensive mistake in this document.

## 4. Nested-route asset paths (silent-failure trap)

A generated page under a subfolder (`/transcript/`) cannot use root-relative `url("assets/…")`.
It resolves to `/transcript/assets/…`, which does not exist — and **Cloudflare Pages answers a
miss with the HTML fallback (HTTP 200, `text/html`)**, so an `<img>` shows nothing useful and a
`background-image` paints *literally nothing*. No broken-image icon, no console error, no clue.

- Re-root to `../assets/…` in the generator (a one-function rewrite over extracted layers), and
  write new declarations that way.
- Verify by fetching the URL and checking `content-type` is an image, not `text/html`.
- Cost of missing this: the Final Days transcript page had never rendered its paper texture or
  any section image wash, for its entire life, through several "verified" visual passes.

## 5. Container-query units follow the nearest ancestor container

`cqi` resolves against the nearest ancestor **container**, not the viewport and not the element
itself. To make type scale identically on a landing page and a content page, the *same* element
must be a container on both — usually the inner `.wrap`, which is capped by `--content`. Getting
this wrong makes the same wordmark visibly different sizes on two pages that are supposed to
match. A container **cannot** be styled by its own query: to vary something for a nested route,
put the query on an ancestor's name and style a descendant.

## 6. Colour: never mix a cool accent into warm paper

```css
/* WRONG — lands on olive/green (measured hue 103 for a blue accent) */
background: color-mix(in oklch, var(--cta) 8%, var(--paper));
/* RIGHT — rebuild the hue from the accent itself */
background: oklch(from var(--cta) 0.96 0.035 h);
```

This trap has now been hit twice in this project (form-field wash, references surface). It is
worth a lint-style habit: any `color-mix` whose two operands differ in hue by more than ~90°
needs a reason.

## 7. Translucent surfaces must be re-verified for contrast

Any change to a surface's alpha changes the effective background:

1. Get the surface colour and the colour behind it **as sRGB** (a canvas `fillStyle`
   round-trip does not convert `oklch()` — parse and convert explicitly, or compute in Node).
2. Composite **in sRGB** (browsers composite non-linear values for `background-color`).
3. Compute WCAG contrast from **linearised** channels; 4.5:1 minimum for body text.
4. If a section also paints an art wash behind the surface, evaluate the worst case with that
   wash at full strength behind, not just the paper.

Reference implementation (validated: `oklch(1 0 0)`→white, `oklch(0.6280 0.2577 29.23)`→red):

```js
function oklch2rgb(L, C, h) {
  const a = C * Math.cos(h * Math.PI / 180), b = C * Math.sin(h * Math.PI / 180);
  const l_ = L + 0.3963377774 * a + 0.2158037573 * b,
        m_ = L - 0.1055613458 * a - 0.0638541728 * b,
        s_ = L - 0.0894841775 * a - 1.2914855480 * b;
  const l = l_ ** 3, m = m_ ** 3, s = s_ ** 3;
  const c = v => { v = Math.min(1, Math.max(0, v)); return v <= 0.0031308 ? 12.92 * v : 1.055 * v ** (1 / 2.4) - 0.055; };
  return [ 4.0767416621 * l - 3.3077115913 * m + 0.2309699292 * s,
          -1.2684380046 * l + 2.6097574011 * m - 0.3413193965 * s,
          -0.0041960863 * l - 0.7034186147 * m + 1.7076147010 * s ].map(v => c(v) * 255);
}
```

Matching an existing callout's translucency (e.g. a `.closing` panel) means matching its
**opacity**, not its hue: keep the surface's own hue and copy the alpha.

## 8. Repeated-item dividers: suppress the first

A rule drawn above every entry in a list must be hidden on the first one — it follows a heading
or summary, not a peer.

```css
.t-ref-entry:first-of-type .t-ref-rule { display: none; }
```

`:first-of-type` is per-parent, so this covers every list (section lists and appendix groups)
without extra classes. Verify by computed style across **all** lists, not just the one you
looked at.

## 8b. Text over a still-strong backdrop: measure the pixels, then decide

A backdrop layer that runs behind the content is at **full strength** near its top: a fade that
starts at 55% of a 793px layer does nothing at y=235, so text placed there sits over artwork.

**Do not assume that is unreadable, and do not assume it needs a panel.** Sampled on the real
rendered pixels at exactly that height, the Final Days mist measured average `rgb(244,240,235)`,
and the page's own text tokens passed comfortably *unaided*:

| Text | Token | Worst case on the real pixels | Typical |
|---|---|---|---|
| Lead headline | `--brand` navy | **6.9:1** | 11–12:1 |
| Note | `--ink-soft` | **4.6:1** | 7.4:1 |

A card was built here first, on the assumption that bare text could not work. The real cause was
paint order (§3a), and the human's next request was to remove the card — a surfaced lead reads
as just another section, which is exactly what a content page should avoid. **Measure first:**

1. Temporarily hide the text's own block with `visibility: hidden` (`display: none` moves the
   layout) so the backdrop composites exactly where the text will sit.
2. Screenshot it and sample that box: average, darkest and lightest pixel.
3. Score the platform's own text tokens against the **worst-case** pixel in the box (§7's
   linearised WCAG method). Body text needs 4.5:1; large or bold text 3:1.

If it passes, ship bare text on the image — it keeps the page from looking like a stack of
identical panels and inherits the real typography. Keep the block's padding when you drop a
surface, so the prose does not move, and keep its `position: relative` (§3a).

If it fails, prefer the page's *existing* content surface (fill, hairline border, radius,
shadow) over a one-off scrim or feathered blob — one shared surface language reads as "the
content column starts here". Do not "fix" it by fading the image earlier; that destroys the
image the page is built around.

Rule of thumb: an unsurfaced block is safe when its **measured** worst case passes. Surfacing it
is a design decision, not an automatic fix.

If text goes missing or looks washed out *after* any of this, stop tuning colour: a block present
in the DOM and absent on screen is a paint-order problem. Go to §3a.

## 8c. Equalize spacing around a repeated block by *replacing* container padding

"Same space above and below this block" fails when the block is last in a padded container: the
upper gap is the block's collapsed margin, the lower gap is that margin **plus** the container's
padding. Do not add margin to compensate — swap the padding:

```css
.t-refs   { margin: var(--t-refs-gap) 0 0; }
.t-section:has(> .t-refs:last-child) { padding-block-end: calc(var(--t-refs-gap) - 1px); } /* -1px = the container border */
```

`:has(> X:last-child)` keeps it conditional, so containers that end with other content keep
their normal padding. Subtract the container's border width or the measurement will be off by
exactly that much — and **measure the result** on every affected container (upper gap, gap
between repeated blocks, lower gap) rather than trusting the arithmetic.

## 9. Orient the reader with words, not a decorative rule

A hairline rule above the content says nothing. A short headline that names the page does, and
it is better for SEO/GEO/AEO and for screen readers. Keep the page's single descriptive `h1`
(a wordmark `h1` with an `sr-only` descriptive span is fine) and use an `h2` for the lead.

## 10. Generated pages: keep the generator the single source

- Generator and generated file must always be in sync; never hand-edit the output only.
- **Rebuilds must be idempotent.** If a preserved zone is re-emitted verbatim, trim its leading
  and trailing whitespace first — otherwise the file grows on every run (this generator was
  growing 6 bytes per build, unnoticed).
- Prove it: rebuild twice and compare byte counts; compare the preserved prose
  whitespace-normalised against the pre-change file.

## Pre-flight checklist for a new content page

- [ ] Masthead: brand block + `n ×` its own top space, `n = 2` unless told otherwise; no
      imported landing height; bottom padding 0 with the space inside `.wrap`.
- [ ] Backdrop: designed image? → own `aspect-ratio`, `100% 100%`, never `cover`; may extend
      below the band; paint order proven with a hit test; `pointer-events: none`.
- [ ] Every asset URL correct for the route depth; fetched and `content-type` checked.
- [ ] Type sizes use the same container basis as the page it must match.
- [ ] All accent-derived surfaces built from the accent's own hue.
- [ ] Contrast recomputed for any alpha/surface change, including the art-wash worst case.
- [ ] First item of every repeating list has no leading divider.
- [ ] Text over a still-strong backdrop: worst-case pixel contrast measured on the rendered
      image (§8b). Bare text is correct when it passes; no panel built on an assumption.
- [ ] The content column is `position: relative` (or each surface is), so a positioned backdrop
      can never paint over static content. Paint order proven with the `pointer-events: auto`
      override in place.
- [ ] Repeated blocks measured: gap above == gap between == gap below (padding replaced, not
      added to; container border subtracted).
- [ ] Headline/content says what the page is; one descriptive `h1`.
- [ ] Generator rebuild is idempotent; generator and output in sync.
- [ ] `node _agent-tools\scripts\audit_page.js <file-or-folder>` → 0 fail.
- [ ] Measure, don't eyeball: `node _agent-tools\scripts\cdp_shot.js <url> <tmp.png> "<eval-js>"`
      returns geometry/colour JSON. Screenshots are for the human; numbers are for the fix.

## Verification tools

| Tool | Use |
|---|---|
| `_agent-tools\scripts\audit_page.js` | static audit: CSS braces, `//` comments, mask-composite, JS parse, div balance, identity metas, image veils |
| `_agent-tools\scripts\cdp_shot.js` | measurement mode: pass an eval expression, read geometry/colour JSON (deletes nothing; write the PNG to a temp path) |
| `_agent-tools\scripts\audit_image_veils.js` | masks/fades on image-backed sections |
| `_agent-tools\scripts\analyze_screenshot_rows.js` | ink bands from a PNG; its decoder is the
  zero-dependency one to copy when you need per-pixel sampling |

**Never** claim a visual result from reasoning alone, and never claim it from a screenshot you
cannot read. Either measure it or hand the human a short list of exactly what to eyeball.
